## 3. 缺陷明细

### D01 分页参数类型错误时返回 HTTP 500

| 字段 | 内容 |
|---|---|
| 缺陷编号 | D01 |
| 标题 | 分页参数类型错误时返回 HTTP 500 而非 400 |
| 严重级别 | S4（轻微） |
| 优先级 | P3（低） |
| 模块 | 水表管理 / `GET /api/meters` 分页参数校验 |
| 版本 | `main@22c7dd3`（报告归档 `44bb372`） |
| 环境 | Windows；JDK 21.0.12；Spring Boot 3.3.5；SQLite；后端 `127.0.0.1:8001`（独立数据库副本） |
| 前置条件 | 使用 admin/admin123 登录并取得 JWT |
| 复现步骤 | 1. `POST /api/auth/login` 获取 token；2. 携带 `Authorization: Bearer <token>` 请求 `GET /api/meters?page=1&pageSize=abc`；3. 观察 HTTP 状态、业务码与响应体 |
| 实际结果 | HTTP 500，`code=INTERNAL_ERROR`，`message=服务器内部错误`，`requestId=req_f7b17869aa814872` |
| 预期结果 | HTTP 400，`code=BAD_REQUEST` 或 `VALIDATION_FAILED`，并给出参数类型错误提示 |
| 测试数据 | 查询参数 `page=1&pageSize=abc`；对照组 `pageSize=0`、`pageSize=9999` 均返回 400 `BAD_REQUEST`，提示“页码须大于0，每页条数须为1至200” |
| 请求追踪号 | `req_f7b17869aa814872`（响应头 `X-Request-Id` 同值） |
| 截图 / 日志 | 非功能测试报告 NFT-09 证据页（该行标记为“不符合预期”）；测试人员本机后端日志 `backend-defect.log` |
| 责任人 | 后端成员（待指派） |
| 状态 | 待修复 |
| 验证结果 | 未验证。修复后需回归 NFT-09、FT-05（分页与搜索）及相邻的筛选/分页接口用例 |

**复现请求与响应（2026-10-20 实测）**

```http
GET /api/meters?page=1&pageSize=abc
Authorization: Bearer <admin JWT>
```

```json
{
  "code": "INTERNAL_ERROR",
  "message": "服务器内部错误",
  "requestId": "req_f7b17869aa814872",
  "timestamp": "2026-10-20T19:25:18.7867739"
}
```

```text
HTTP/1.1 500
X-Request-Id: req_f7b17869aa814872
```

**影响分析**

- 前端界面始终发送数字类型的 `pageSize`，正常用户操作不会触发该缺陷，因此不影响当前演示流程。
- 对外提供接口时，非法参数返回 500 会污染错误码约定、干扰监控告警，并可能被误判为服务故障。

**修复建议**

在 `GlobalExceptionHandler` 中补充 `MethodArgumentTypeMismatchException`（以及必要的 `ConstraintViolationException`）处理，统一返回 400 `BAD_REQUEST`，并在 `message` 中说明哪个参数类型不合法；修复后补充一条接口自动化用例，断言 `pageSize=abc` 返回 400 且响应含 `requestId`。
