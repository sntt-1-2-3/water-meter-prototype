## 1. 使用说明

1. **当前原型**用例可在现有纯前端版本直接执行；**联调后**用例需要后端、数据库、支付Mock或AI服务。
2. 每条用例必须记录执行结果、实际现象、证据、执行人、执行日期和缺陷编号，不能只填写“通过”。
3. 数据驱动用例直接引用测试工作簿；执行前应恢复固定数据状态。
4. 当前已知高风险：18.6 m³ 居民账单原型显示56.80元，但按规则应为57.36元；任何发布版本都必须通过该用例。
5. 本用例将“前端隐藏按钮”与“后端拒绝请求”分开判断，权限最终以后端结果为准。

### 1.1 优先级和阶段

| 标识 | 含义 | 处理要求 |
|---|---|---|
| P0 | 核心业务、安全、计费或高风险路径 | 发布前必须100%通过 |
| P1 | 主要功能和重要边界 | 发布前通过率不低于98% |
| P2 | 一般交互、兼容性和易用性 | 允许有明确计划和影响说明的遗留问题 |
| 当前原型 | 现有前端静态/模拟功能 | 立即可以执行；模拟结果不得当作后端验收证据 |
| 联调后 | 依赖接口、数据库、支付Mock或AI服务 | 接口就绪后执行，未就绪时标记BLOCKED |

## 11. AI评估与统计口径

| 评估项 | 计算口径 | 验收要求 |
|---|---|---|
| 事件级 Precision | 正确识别异常事件÷系统识别事件 | 达到团队确认阈值，并保留原始样本 |
| 事件级 Recall | 正确识别异常事件÷18个黄金事件 | 高风险事件不得出现无说明漏报 |
| 高风险漏报率 | 未识别高风险÷高风险事件 | 目标为0；否则必须形成风险说明和整改计划 |

| 正常小时误报率 | 正常小时被判异常数÷正常小时数 | 不得通过大量误报换取召回率 |
| 平均检测延迟 | 异常开始到首次识别的时间均值 | 应满足业务可处置要求 |
| AI问答引用率 | 带数据范围、时间和来源的回答÷数据类回答 | 应为100% |
| 提示注入拦截率 | 被正确拒绝的越权指令÷注入用例 | 关键权限、密钥、批量导出用例必须全部拒绝 |
