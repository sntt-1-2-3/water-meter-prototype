## 1. 编制目的

本计划用于指导智水云 AI 水表收费管理系统的功能测试、接口测试、权限测试、计费测试、AI 异常识别评估、安全边界测试、非功能测试和最终验收。计划以测试数据中的预期结果为基准，以交付版本的实际功能为测试对象，建立“需求—用例—数据—结果—缺陷”的追踪关系。

V1.0 编制于原型阶段，用于识别“界面展示”与“真实能力”的差距；V1.1 根据 Java + Vue 交付版本更新，重点回答以下问题：

1. 当前交付版本已经实现什么，哪些能力仍属于明确的边界（模拟采集、模拟支付、CSV 导出、本地 AI）。
2. 测试数据中的每一类数据分别用于验证什么，与 Java 版种子数据的对应关系是什么。
3. 前后端联调环境如何搭建、如何隔离数据库，避免影响演示库。
4. 如何判断功能、计费、权限、AI 边界和非功能指标是否达到验收条件。
5. 每项需求如何追溯到用例、执行证据与缺陷。

## 3. 系统与当前基线

### 3.1 技术基线

| 层次 | 当前实现 |
|---|---|
| 前端 | Vue 3.5 + TypeScript + Vite 8，Pinia、Vue Router、Element Plus、ECharts、Axios |
| 后端 | Java 17 编译目标，Spring Boot 3.3.5，Spring Data JPA，Spring Security + JWT（HS512） |
| 数据库 | SQLite（sqlite-jdbc 3.46.1.3），Hikari 连接池 1，启动时自动建表并写入种子数据 |
| 认证 | BCrypt 口令哈希；JWT 每次请求回查账号启用状态、角色、辖区与绑定关系 |
| AI | 默认本地规则引擎（按当前账号权限读取真实数据）；可选 DeepSeek，需自行配置密钥 |
| 启动 | 根目录 `start-all.bat`，或分别执行 `start-backend.bat` 与 `start-frontend.bat` |
| 端口 | 前端 5173（Vite）、后端 8000（Spring Boot）、Swagger 8000/swagger-ui.html |
| 演示账号 | admin、operator_east、finance01、auditor01、user_res_001、user_com_001（禁用），初始口令 admin123（BCrypt 存储） |

### 3.3 与 V1.0 的主要差异

- 后端由“缺失”变为 Spring Boot + SQLite 实际服务，登录、权限、计费、采集、异常、反馈、通知均已落库。
- 前端由单文件原型拆分为路由、页面、组件、Pinia 状态和 API 客户端。
- 计费规则与 18.6 m³ = 57.36 元的口径已在后端自动化测试中覆盖。
- 报表由“仅提示成功”变为真实 CSV 下载；.xlsx、PDF 与独立日报/周报/月报服务仍未实现，属于明确边界。
- AI 由硬编码回答变为按权限读取数据库的本地规则引擎；外部 DeepSeek 未纳入本轮验收。

## 4. 测试范围

### 4.1 范围内

- 登录、角色、菜单权限、按钮权限和数据范围（前端 + 后端接口双重校验）。
- 水表档案查询、筛选、分页、新增、编辑和详情。
- 自动抄表、模拟失败、补抄、重试、任务幂等和定时开关。
- 居民阶梯水价、商业统一价、工业合同价、违约金、账单快照与模拟缴费。
- 异常识别、分级、去重、人工确认与处置闭环。
- 运营总览指标、图表统计与统计口径。
- 用户端用水、账单、模拟缴费、通知和异常反馈。
- AI 数据问答的数据范围、无数据回答和安全边界。
- CSV 报表导出、错误处理、会话管理、审计日志落库。
- 数据质量、接口错误码、幂等、并发、性能、安全、兼容性、可靠性与易用性。

### 4.2 范围外（交付版本声明的边界）

- 真实银行、微信或支付宝的资金清算；本轮缴费为本地模拟记账（SIMULATED）。
- 真实公网大模型的费用结算与效果验收；外部 DeepSeek 未纳入本轮。
- 真实水表硬件的通信协议与现场验收；采集为后端模拟场景。
- .xlsx、PDF 导出以及独立的日报、周报、月报生成服务。
- 操作日志的独立检索页面或下载接口（日志已落库）。
- 生产级多实例并发、HTTPS 与密钥托管等部署能力。

范围外能力若用于演示，必须标注为模拟，不得在报告中表述为已完成。

## 5. 质量风险

| 风险 | 影响 | 应对措施 |
|---|---|---|
| SQLite 连接池为 1，写入串行 | 高并发下延迟上升 | 本地原型接受；并发用例以“不失败、不超时”为判定，不承诺容量 |
| 报表为 CSV，不是 Excel/PDF | 验收项 TC-019 无法按原口径通过 | 在报告中明确能力边界，避免误解为已支持 xlsx/PDF |
| AI 为本地规则引擎，未接入外部模型 | AI 效果评估缺少模型侧指标 | 单独记录为边界；如接入 DeepSeek 需重新评估 |
| 跨域使用 allowedOriginPatterns("*") 且允许携带凭据 | 公开部署存在风险 | 记录为观察项 O02，部署前收敛为白名单 |
| 分页参数类型错误返回 500 | 接口健壮性与错误码不一致 | 缺陷 D01，建议补充 400 处理并回归 |
| 单个页面 chunk 超过 500 kB | 首屏体积偏大 | 观察项 O03，按需引入 ECharts、拆分 vendors |
| 测试数据工作表与 Java 种子数据规模不同 | 用例数量与执行记录容易混淆 | 明确区分“设计基线（工作簿）”与“运行基线（种子数据）” |
| 演示账号口令为公开的 admin123 | 仅适合本地演示 | 部署前必须更换账号策略与密钥 |

## 6. 测试策略

采用基于风险的测试策略，按以下顺序推进：

1. 先验证启动、构建、数据加载和基础页面冒烟。
2. 再验证数据校验、计费和权限这些高确定性规则。
3. 随后验证抄表、异常、账单、反馈和通知的集成闭环。
4. 对 AI 实施独立的边界测试，不把“界面能回答”等同于 AI 验收通过。
5. 最后执行端到端验收、非功能测试、回归、部署复现和材料证据整理。

每个测试结论必须能够追溯到需求、测试用例、测试数据和执行证据。没有实际执行证据的用例不得填写“通过”。

### 11.2 计费测试设计

计费测试必须覆盖以下边界：

- 居民 0—12 m³：单价 2.80 元/m³。
- 居民 12—20 m³：前 12 m³ 按 2.80 元，其余按 3.60 元。
- 居民超过 20 m³：前 12 m³ 按 2.80 元，12—20 m³ 按 3.60 元，超出部分按 5.20 元。
- 商业统一价：4.20 元/m³。
- 工业合同价：5.10 元/m³。
- 违约金：按逾期规则计算，验证天数边界和金额取整。
- 四舍五入：统一到分，禁止前后端不同口径。
- 幂等：同一周期重复生成时返回原批次或明确拒绝，不能重复入账。
- 边界值：0、12、20、18.6、100 m³，以及小数进位临界值。

18.6 m³ 按阶梯规则应为 57.36 元，作为计费回归的首个必测样本，已由 `BillingServiceTest.testKnownDiscrepancySample_18_6` 覆盖。

### 11.3 数据质量测试设计

按`数据质量用例`执行 DQ-001—DQ-025，重点验证：

- 必填字段为空。
- 水表编号不存在或格式错误。
- 瞬时流量或累计流量为负。
- 累计流量倒退。
- 时间戳为空、格式错误、未来时间或早于安装时间。
- 水温超出合理范围。
- 阀门状态或报警码非法。
- 重复上报、时间冲突和频率过高。
- 报警码与阀门状态冲突。
- 离线设备恢复正常上报。

每个拒绝用例必须同时校验 HTTP 状态码、业务错误码、错误提示、是否写入数据库以及是否产生审计记录。不能只检查前端提示。

### 11.4 权限测试设计

按`权限用例`执行 PERM-001—PERM-024。权限测试必须同时覆盖：

1. 前端菜单和按钮是否隐藏。
2. 直接构造接口请求时后端是否拒绝。
3. 查询结果是否按区域、本人或其他数据范围过滤。
4. 审计人员是否真正只读。
5. 普通用户是否只能访问本人水表、账单和反馈。
6. AI 工具是否继承当前用户权限。
7. AI 写操作是否必须二次确认。
8. AI 是否拒绝输出无来源统计结论或越权数据。

前端隐藏按钮不能算权限通过，必须以接口测试结果作为最终依据。

### 11.5 AI 异常识别评估

输入仅使用原始上报数据中的表具编号、时间戳、瞬时流量、累计流量、水温、阀门状态和报警码。异常标签和工作表中的预期字段只用于结果比对。

推荐划分方式：

- 按水表编号划分训练集和测试集，避免同表相邻记录泄漏。
- 评估单位为异常事件，不使用行级准确率替代事件识别效果。
- 评估指标包括事件级 Precision、Recall、F1、高风险漏报率、各异常类型召回率、正常小时误报率、平均检测延迟。
- 至少验证持续高流量、夜间小流量、累计流量倒退、阀门故障 E03、水表离线和数据突变。
- 高风险漏报应优先修复；AI 结果不得直接扣费、处罚用户或关闭工单。

本轮状态：Java 版未提供事件级评估接口，18 个黄金事件的 P/R/F1 评估报告尚未产出，列为待补交付物。

### 11.6 AI 助手与安全边界

- 回答必须带统计时间范围、数据范围和来源。
- 查询不存在区域时应明确说明无数据。
- 要求导出全部用户、忽略权限或修改账单时必须拒绝。
- 多轮提问不得通过上下文绕过权限。
- 模型不可用时显示可理解的降级提示，不得编造结果。
- 日志不得记录完整敏感字段、API 密钥或明文密码。
