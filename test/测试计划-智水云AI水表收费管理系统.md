## 1. 编制目的

本计划用于指导智水云 AI 水表收费管理系统的功能测试、接口测试、权限测试、计费测试、AI异常识别评估、安全边界测试和最终验收。计划以测试数据中的预期结果为基准，以原始系统中的实际功能为测试对象，建立“需求—用例—数据—结果—缺陷”的追踪关系。

本计划重点回答以下问题：

1. 当前原型已经实现什么，哪些只是界面展示。
2. 测试数据中的每一类数据分别用于验证什么。
3. 前后端联调后应按什么顺序执行测试。
4. 如何判断功能、计费、权限和 AI 边界是否达到验收条件。
5. 如何记录证据、缺陷和测试结论，形成可提交的测试文档。

## 3. 系统与当前基线

### 3.1 技术基线

当前源码为 Vue 3 + TypeScript + Vite 单页前端原型，使用 Element Plus 和 ECharts。`package.json` 当前只提供：

```text
npm run dev
npm run build
npm run preview
```

项目当前缺少后端服务、数据库、登录鉴权、真实REST API、审计日志和真实文件导出能力。

### 3.2 当前功能实现情况

| 模块 | 当前实现 | 测试重点 |
|---|---|---|
| 管理员端/用户端切换 | 前端角色变量切换 | 未登录访问、角色越权、菜单和数据范围 |
| 运营总览 | 静态指标、静态图表、模拟抄表按钮 | 指标口径、刷新状态、失败保留旧数据、数据一致性 |
| 水表管理 | 6条静态数据，搜索和类型筛选可用 | 60台测试数据加载、组合筛选、分页、新增编辑、详情 |
| 抄表中心 | `setInterval` 随机进度 | 幂等、漏抄、补抄、重试上限、失败转异常 |
| 计费账单 | 静态水价和账单批次，确认后只提示成功 | 阶梯边界、金额取整、违约金、幂等、账单追踪 |
| 异常中心 | 5条静态异常，状态按钮直接切换 | AI识别、风险分级、人工确认、派单、闭环、审计 |
| 统计报表 | 按钮只显示“暂不下载真实文件” | Excel/PDF真实下载、字段完整性、任务记录 |
| 用户端 | 静态账单、用水量、通知和操作入口 | 本人数据隔离、缴费幂等、历史账单、异常反馈 |
| AI助手 | 通过 `if` 关键词返回硬编码答案 | 数据问答、引用来源、权限过滤、无数据回答、提示注入 |
| WebMCP | 3个工具原型 | 工具参数、只读/写操作、权限确认、异常处理 |
| 响应式 | CSS存在1180/840/560px断点 | 桌面、平板、手机、抽屉和表格可用性 |

## 4. 测试范围

### 4.1 范围内

- 登录、角色、菜单权限、按钮权限和数据范围。
- 水表档案查询、筛选、分页、新增、编辑和详情。
- 自动抄表、漏抄识别、补抄、重试、幂等和失败转异常。
- 居民阶梯水价、商业统一价、工业合同价、违约金和账单生成。
- 异常识别、分级、人工确认、派单、处置、反馈和归档。
- 运营总览指标、图表统计和统计口径。
- 用户端用水、账单、缴费、通知和异常反馈。
- AI异常识别效果、AI助手回答质量和AI安全边界。
- Excel/PDF报表导出、审计日志、错误处理和部署复现。
- 数据质量、接口错误码、幂等、并发和边界值。

### 4.2 范围外

- 真实银行或第三方支付机构的资金清算。
- 真实公网大模型账号申请和费用结算。
- 真实生产水表硬件通信协议的现场验收。
- 与赛题无关的浏览器历史版本兼容性。

上述范围外能力若要演示，可使用Mock支付、Mock模型或模拟器，但必须在测试报告中明确标注为模拟。

## 5. 质量风险

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 只有前端原型，没有后端和数据库 | 大量验收用例无法执行 | 先建立前后端联调环境和种子数据，接口未完成时标记 BLOCKED |
| 页面数据与测试数据规模不一致 | 查询、分页和统计结果不可信 | 统一为60台测试水表作为测试环境基准 |
| 居民账单显示56.80元，规则计算为57.36元 | 计费准确性失败 | 统一阶梯、附加费、小数位和四舍五入口径并回归 |
| AI回答硬编码 | AI功能不真实，无法引用数据 | 接真实数据工具并验证来源、权限和失败降级 |
| 角色切换仅在前端 | 可绕过权限访问数据 | 后端必须重新鉴权，前端隐藏不作为权限依据 |
| 报表导出未生成文件 | 验收项无法完成 | 实现真实文件下载并校验内容 |
| 异常状态直接切换 | 缺少确认、工单和审计 | 建立状态机、确认人、时间线和日志 |
| 测试账号密码为初始口令 | 安全风险 | 数据库种子加载时改为BCrypt哈希，并禁止明文存储 |

## 6. 测试策略

采用基于风险的测试策略，按以下顺序推进：

1. 先验证构建、启动、数据加载和基础页面冒烟。
2. 再验证数据校验、计费和权限这些高确定性规则。
3. 随后验证抄表、异常、账单和工单的集成闭环。
4. 对AI实施独立的离线评估，不把“界面能回答”等同于AI验收通过。
5. 最后执行端到端验收、回归、部署复现和材料证据整理。

每个测试结论必须能够追溯到需求、测试用例、测试数据和执行证据。没有实际执行证据的用例不得填写“通过”。

### 11.2 计费测试设计

计费测试必须覆盖以下边界：

- 居民0—12 m³：单价2.80元/m³。
- 居民12—20 m³：前12 m³按2.80元，其余按3.60元。
- 居民超过20 m³：前12 m³按2.80元，12—20 m³按3.60元，超出部分按5.20元。
- 商业统一价：4.20元/m³。
- 工业合同价：5.10元/m³。
- 违约金：按逾期规则计算，必须验证天数边界和金额取整。
- 四舍五入：统一到账单位，禁止前端和后端使用不同口径。
- 幂等：同一周期重复生成时返回原批次或明确拒绝，不能重复入账。
- 边界值：0、12、20、18.6、100 m³，以及小数进位临界值。

已知口径不一致样本：18.6 m³按阶梯规则应为57.36元，当前原型展示56.80元。该样本必须作为计费回归的首个必测用例。

### 11.3 数据质量测试设计

按`数据质量用例`执行DQ-001—DQ-025，重点验证：

- 必填字段为空。
- 水表编号不存在或格式错误。
- 瞬时流量或累计流量为负。
- 累计流量倒退。
- 时间戳为空、格式错误、未来时间或早于安装时间。
- 水温超出合理范围。
- 阀门状态或报警码非法。
- 重复上报、时间冲突和频率过高。
- 报警码与阀门状态冲突。
- 离线设备恢复正常上报。

每个拒绝用例必须同时校验HTTP状态码、业务错误码、错误提示、是否写入数据库以及是否产生审计记录。不能只检查前端提示。

### 11.4 权限测试设计

按`权限用例`执行PERM-001—PERM-024。权限测试必须同时覆盖：

1. 前端菜单和按钮是否隐藏。
2. 直接构造接口请求时后端是否拒绝。
3. 查询结果是否按区域、本人或其他数据范围过滤。
4. 审计人员是否真正只读。
5. 普通用户是否只能访问本人水表、账单和反馈。
6. AI工具是否继承当前用户权限。
7. AI写操作是否必须二次确认。
8. AI是否拒绝输出无来源统计结论或越权数据。

前端隐藏按钮不能算权限通过，必须以接口测试结果作为最终依据。

### 11.5 AI异常识别评估

输入仅使用原始上报数据中的表具编号、时间戳、瞬时流量、累计流量、水温、阀门状态和报警码。异常标签和工作表中的预期字段只用于结果比对。

推荐划分方式：

- 按水表编号划分训练集和测试集，避免同表相邻记录泄漏。
- 评估单位为异常事件，不使用行级准确率替代事件识别效果。
- 评估指标包括事件级Precision、Recall、F1、高风险漏报率、各异常类型召回率、正常小时误报率、平均检测延迟。
- 至少验证持续高流量、夜间小流量、累计流量倒退、阀门故障E03、水表离线和数据突变。
- 高风险漏报应优先修复；AI结果不得直接扣费、处罚用户或关闭工单。

### 11.6 AI助手与安全边界

- 回答必须带统计时间范围、数据范围和来源。
- 查询不存在区域时应明确说明无数据。
- 要求导出全部用户、忽略权限或修改账单时必须拒绝。
- 多轮提问不得通过上下文绕过权限。
- 模型不可用时显示可理解的降级提示，不得编造结果。
- 日志不得记录完整敏感字段、API密钥或明文密码。

## 15. 暂停与恢复条件

发生以下情况时暂停测试并记录阻塞：

- 测试环境无法启动或测试库无法重置。
- 登录鉴权不可用，无法区分角色。
- 测试数据与预期答案版本不一致。
- 计费规则或水价版本发生变更但未通知测试。
- 后端接口大面积不可用。
- AI模型或工具调用导致敏感数据泄露风险。

阻塞原因、影响用例、责任人、临时措施和恢复时间必须写入测试执行记录。

## 16. 缺陷管理

### 16.1 严重级别

| 级别 | 定义 | 示例 |
|---|---|---|
