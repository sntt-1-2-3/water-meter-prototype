# 照片识别抄表使用说明

本模块在现有 Java + Vue 系统内增加照片读数采集，不替代原来的软件模拟采集。图片在本机 Java 后端使用 OCR 处理，不需要大模型 API Key，不向云端识别服务发送照片。

## 如何操作

1. 使用管理员或有对应区域权限的运营账号登录，进入“抄表中心”。财务、审计和居民账号不能上传、读取或确认照片。
2. 在“照片识别抄表”中选择对应水表，再选择 JPEG / PNG 照片；手机可使用拍照入口。每张照片不超过 8 MiB，图像解码前检查不超过 1200 万像素。HEIC、SVG、PDF 和伪装成图片的文件不接受。
3. 上传后显示原图、候选读数和确认表单；OCR 原文及参考分数在“识别详情”中展开查看。此时只保存待确认草稿，不改变水表读数，也不生成账单。
4. 如果整张表盘的型号、编号等干扰识别，可在原图拖动框选数字滚轮区域，再重新识别；朝向不对时先旋转。应包含完整数字，避免把下面的表号、倍率、指针小表盘一起选入。
5. 选择候选读数或手工填写，仔细核对 m³ 单位、红黑数字和小数点。检测到可靠黑红滚轮分界时，会按末尾红字数量给出小数建议，并显示自动选区及识别依据；仍须人工核对。没有可靠分界时，不根据数字长度猜测小数位，可手动选择 0–3 位小数调整。例如黑字 `00070`、红字 `812` 对应的建议为 `70.812`。
6. 核对“当前累计读数”“确认读数”和“本次增加用量”，填写修正说明，勾选已核对原图，再点击确认并在二次提示中确认保存。
7. 保存后显示“已确认入库”。正式读数会更新水表档案、用水统计，并在后续生成该账期账单时使用。历史记录保留原图、识别原文、最后采用的数字、确认人、时间和修改说明。

## 上传进度与识别超时（2026-11-10）

页面现在分两步处理：先上传并保存照片草稿、加载原图，再单独进行 OCR。上传百分比仅代表文件传输进度，不代表读数已经识别或入库；保存成功后显示独立的加载/识别状态。

本地 OCR 默认最多等待 20 秒，可用 `PHOTO_OCR_TIMEOUT_SECONDS` 配置（实际限制为 1–45 秒）。引擎忙或超时时返回明确提示和空候选，不生成假读数。识别任务只有一个工作线程、不排队；原生库即使忽略中断，也不会继续创建线程或堆积照片请求。原生调用仍未结束时，新的识别会提示繁忙，已有照片仍可人工核对；必要时正常重启后端以恢复引擎。

点击“停止等待”会取消浏览器等待，保留已保存的草稿，不表示服务器一定已经停止当前处理。可在照片记录里打开草稿，或点“刷新草稿”恢复原图，再重新识别或人工填写。上传超时但尚未返回照片编号时，请先刷新历史记录，避免重复上传。

上传请求限时 30 秒、原图/历史查询限时 15 秒，识别请求客户端最多等待 55 秒（覆盖服务端配置的上限）。后台历史记录刷新不再锁住整个上传表单。

本次验证：前端构建通过；后端 113 项测试通过（无失败、错误或跳过），含不执行 OCR 即保存照片、后续识别、无 OCR 人工确认、原生调用忽略中断时的超时返回及忙碌拒绝。打包首次受测试进程占用 JAR 影响，停止该测试进程后重新打包成功。更新前独立测试库的真实 HTTP 样例上传返回 200，耗时约 1.7 秒，未复现用户报告的永久转圈。更新后的完整浏览器上传流程尚未验收；自动选文件受扩展本地文件访问限制，启动临时复测服务另被自动审批拦截。

后端需要重启后才会使用新的等待限制。前端在 Vite 下支持热更新，必要时强制刷新浏览器。不要同时启动两个后端写同一个数据库。

## 与计费的关系

- 识别建议不参与计费，只有人工确认后新增的正式读数才参与。
- 本次用水量取累计读数增量，不把照片识别结果当成本月用水量；也不凭照片虚构瞬时流量、水温、阀门状态或报警码。
- 应先确认照片读数，再由 ADMIN / FINANCE 进入“计费账单”生成账期快照。
- 已经生成的当期账单是不可覆盖的快照。为避免出现“保存了新读数但账单没变”的误会，同一水表已有当期账单时不能再确认当期新照片；不会偷偷重算、删除或修改已缴账单。
- 更新期间有另一人或采集任务改变了该表的最新读数，确认会返回冲突；重新加载草稿，按新的当前读数核对后再提交。
- 同一草稿重复确认相同数字不会重复写读数；已确认草稿不能改成另一个数字，也不能重新识别覆盖审核证据。

## 数字窗口与逐位识别（2026-11-10 后续更新）

针对整图把型号 `131.68` 当成读数的问题，增加了保守的机械滚轮定位：按颜色连通区域、数字高度、间距及排列关系，寻找至少三个黑字滚轮后跟 2–3 个红字滚轮的行。位置来自图片内容，不依赖某张照片的固定坐标或答案。

定位后将每个数字的前景从灰色隔条、黑底与邻近半转字符中分离，用两种 Tesseract 分割模式逐位识别。两次结果须一致，才能组合完整建议；无法稳定读取某一位时显示 `?`，不拼成假读数。自动选区会保存为旋转后原图坐标，重新打开草稿仍能显示。

只有明确检测到连续的红色末位时才给出小数建议；数字串、红字位数及人工核对提醒保留在 OCR 原文中。整图无法可靠定位时，型号、编号和倍率等普通文字不会再自动填入建议读数；可人工框选后重试。此版主要改善正向、清晰的黑红机械滚轮；斜拍、反光、黑底白字、一个红字位或指针表仍可能需要人工处理。

公开真实样例 `water-meter-aka.jpg` 已在原生 OCR 测试中从整图、人工裁剪和缩放/平移变体得到 `70.812`；另一组合成读数及两位红字得到 `123.45`。倾斜样例仍不能可靠定位，会返回需人工处理，不能据这些样例宣称通用准确率。完整浏览器上传及新版选区展示仍需页面验收。

本次最终验证：`npm run build` 通过；`mvn.cmd package -Dphoto.ocr.native=true` 共 121 项测试全部通过，无失败、错误或跳过，打包成功。包含自动选区经旋转/裁剪映射并重载、超出支持位数时拒绝而非截掉首位、型号/编号不得作为整图读数建议等回归用例。测试使用独立数据库，没有更改现有住户的累计读数或账单。

**样例与现有住户不同：**此图 `70.812 m³` 小于截图里 A-00218 的 `1033 m³`，所以即使识别正确也不能确认入库。请在独立测试库中使用起始读数低于该值的测试水表验证计费，不要降低真实/已有住户的累计读数来迁就样例。

分割模式、数字白名单及字典设置参考 [Tesseract 官方识别质量说明](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)，实现不新增 Python 服务、云端调用或付费依赖。

## 识别范围与失败处理

OCR 使用开源 [Tess4J](https://github.com/nguyenq/tess4j) / Tesseract 本地识别。它是字符识别，不是针对各种水表训练并验收过的专用表盘模型。参考分数不是“正确概率”，即使分数较高也必须人工核对。

本版锁定 Tess4J **5.19.0**，不是盲目使用最新版：5.20.0 在本机 Windows / Java 21 出现原生初始化错误，和 [官方问题 #286](https://github.com/nguyenq/tess4j/issues/286) 一致；5.19.0 已通过本机真实 OCR 测试。

机械滚轮的半转数字、反光、模糊、倾斜、污损、黑底白字、红字小数位都可能误读。指针式小表盘、本位制自动推断、加仑自动换算不在本版保证范围内。多个候选、识别不到或本机引擎暂不可用时会显示原因，不填入假读数；仍可查看原图后人工填写并确认，审核记录会标记人工调整。

Windows 的 OCR 原生库由 Maven 依赖提供，需要 Microsoft Visual C++ v14 运行库。其他操作系统还需要相应的 Tesseract / Leptonica 原生库。首次构建需联网下载依赖，识别本身不需要网络。安装前置条件见 [Tess4J 官方说明](https://github.com/nguyenq/tess4j#dependencies)。不要为修复 OCR 去关闭系统安全功能。

## 数据与权限

图片以验证后的 PNG 存在本地 SQLite 数据库，不使用用户提供的路径或公开静态目录；规范化重编码去除原照片的 EXIF 元数据。读取照片需要有效登录和相应水表管理权限，不把 JWT 放进图片 URL。

请在升级前关闭后端并备份 `backend/water.db`。照片会增大数据库文件；共享源码时不要上传数据库、JWT 密钥或真实用户照片。演示请用独立数据库和 [公开授权测试样例](examples/README.md)，不要将样例数字写入真实住户的水表。

## 开发接口

均以 `/api` 为前缀，均要求 ADMIN / OPERATOR 并验证区域权限。

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 保存照片草稿 | `POST /readings/photos` | multipart：`meterId`、`file`、`recognize=false`；先保存原图，前端随后调用识别接口；省略 recognize 兼容原先的上传后识别行为 |
| 历史列表 | `GET /readings/photos` | 可按 `meterId` 筛选，`page` / `pageSize` 分页 |
| 草稿或已确认详情 | `GET /readings/photos/{id}` | 包含当前基线、识别和审核字段 |
| 受保护原图 | `GET /readings/photos/{id}/image` | 返回 PNG 二进制，不是 ApiResponse JSON |
| 框选/旋转后重识别 | `POST /readings/photos/{id}/recognize` | `rotation` 为 0/90/180/270；`crop` 使用旋转后整图的像素坐标 |
| 人工确认 | `POST /readings/photos/{id}/confirm` | `reading`、`expectedPreviousReading` 均为十进制字符串，可带 `note` |

读数最多 9 位整数、3 位小数，禁止负数、科学计数法、累计倒退或陈旧基线。前端以字符串和整数千分位计算，后端用 BigDecimal；OCR 原文及客户端输入均视为不可信数据，不作为权限依据。
